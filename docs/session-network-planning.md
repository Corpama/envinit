# 会话记录：网卡自动发现与规划

整理日期：2026-10-22；本次补充：2026-11-12。实现细节参见 [网卡发现设计](nic-discovery-design.md)；未完成事项参见 [验收专项](session-rerun-acceptance.md)。

## 现场使用背景与两种入口

本专项的目标不是要求现场先把 inventory 补成“完整硬件资产表”，而是让工具能够从网络规划逐步完成机器初始化。现场存在两种主要入口，二者的输入事实不同，但最终都应收敛到同一个“规划目标 + 现场事实 + 人工确认”的执行模型。

### 场景一：只有网络规划表，从本机/控制台开始初始化

开局时通常只有网络规划表。规划表可能包含：

- 机器身份，以及管理网和 RoCE/RDMA 网的目标接口名或逻辑槽位名；
- 管理网 IP、prefix、网关；
- 每个 RoCE/RDMA 口的 IP、prefix、网关；
- 可能包含管理网是单口还是 bond 的规划。

规划开始时通常不知道各口 MAC。目标机还可能处于以下任一状态：

1. 管理网已插线且交换机已配置，RoCE 口未插线；
2. RoCE 口已插线，但交换机尚未配置；
3. RoCE 口已插线且交换机已配置，管理网也已配置；
4. 管理网或 RoCE 网均未达到可连通状态。

这个场景下，工具需要从本机执行（例如现场控制台、带外进入的系统或其他可在目标机运行工具的方式），完成：

1. 读取本机网卡事实，收集当前名称、MAC、型号、速率、carrier、RDMA 能力和当前地址；
2. 将规划表中的管理口和 RoCE/RDMA 槽位绑定到真实物理网卡；
3. 对没有 MAC、链路或交换机证据的槽位，不能因为“未插线”或“网关不可达”就删除或跳过规划；应保留槽位并进入人工确认，或使用明确的硬件分组/名称证据绑定；
4. 初始化管理网和 RoCE/RDMA 网，包括地址、路由、policy rule、持久化命名和相关网络后端配置；
5. 按 bundle 选择执行 OFED、驱动、XDR、固件、容器、mlxconfig、sysctl、kernel、post 等后续 stages。

交换机不可达只代表当前缺少连通性证据，不代表主机侧不能先写入规划配置。工具必须把“已确认绑定但尚未验证连通性”和“尚未确定物理绑定”区分开，不能把二者都静默当作成功。

### 场景二：管理网已就绪，通过 SSH 远程初始化或补配置

部署人员已经可以通过管理网 SSH 登录目标机，管理网本身不需要重新规划或通常只需核对。RoCE/RDMA 以及后续配置可能处于两种状态：

1. **RoCE 口已插线但交换机尚未配置，主机侧可能没有 RoCE IP。** 工具需要通过 SSH 收集网卡名称、MAC、型号、RDMA 能力、链路和当前地址等事实，然后根据已有规划表绑定 RoCE 槽位，写入 RoCE IP、网关、路由和后续调优；
2. **RoCE 口已经配置了 IP，但尚未完成后续调优或特定路由。** 工具需要通过 SSH 收集当前状态，核对规划 IP/prefix/接口对应关系，再补齐缺失的路由、policy rule、持久化命名、QoS/硬件调优和其他 stages。

这个场景会使用 `discover` 收集现场事实，使用 `apply` 执行目标状态变更。SSH 控制地址只是本次连接入口，不应被误认为是新的管理网规划地址；`discover` 发现到的当前 IP、MAC 和接口名也不应无条件覆盖规划表中已经确认的目标 IP、网关和逻辑槽位。

当前源码的 `discover` 主要通过 `show_gids` 和 IPv4 信息发现已存在的 RDMA 候选，并在没有 IPv4 RDMA 条目时可能报“没有 IPv4 show_gids RDMA entries”。因此，场景二的第一种子场景（RoCE 已插线但主机尚未配置 RoCE IP）目前仍是实现缺口：后续应支持“仅有硬件/RDMA 能力和链路事实、没有当前 RoCE IP”的发现结果，再由规划表提供目标 IP/prefix/网关。

## 统一原则：规划目标与现场事实分离

两种场景都需要区分以下三类信息：

| 信息类别 | 来源 | 例子 | 处理方式 |
| --- | --- | --- | --- |
| 规划目标 | 规划表/bundle | 目标接口名、逻辑槽位、IP、prefix、网关、管理模式 | 作为 apply 的目标，不因当前未连通而丢弃 |
| 现场事实 | apply 本地采集或 discover SSH 采集 | MAC、当前接口名、carrier、当前 IP、MTU、RDMA device、PCI、速率 | 用于绑定、核对和提示；事实不自动替代目标 |
| 人工确认 | NIC Binding Review/Network Discovery Review | 某个物理口对应 mgmt 或 rdmaN、槽位顺序 | 形成最高优先级的本次执行绑定，可持久化复用 |

初始规划表不应以 MAC 是否已知作为能否开始的门槛；MAC 是现场发现和确认后补充的事实。相反，IP、prefix、网关和 RoCE 槽位数量属于网络规划目标，不能因为 discover 当前没有读到而被清空。

## 最小开局输入

面向场景一的最小规划不应包含硬件 MAC，但至少需要提供：

- 唯一的 `hostname`，作为规范机器身份；旧 inventory 的 `host_id` 仅作为兼容输入；
- `mgmt_mode`（`single`、`bond` 或 `auto`）；规范 examples 显式填写，不能只靠当前发现到几张网卡来猜测；
- 管理网目标 IP、prefix、网关；
- RoCE/RDMA 规划槽位及其目标 IP、prefix、网关；
- 规划中的目标接口名可以作为逻辑名称或初始提示，但不能当作 MAC 级别的物理证明。

以下字段属于现场事实或高级覆盖，初始表可以为空或不出现：`mgmt_mac1/2`、`rdmaN_mac`、当前物理接口名、`rdmaN_rail_id`、`rdmaN_table` 和 `rdmaN_route_cidr`。规范 inventory 逐机提供管理/RDMA 的 prefix 和网关；DNS 使用 bundle defaults，不在普通 inventory 中重复填写。不能把 prefix 完全省略后依赖静默 `/24`，也不能在没有规划依据时猜测非 `.1` 网关。

## 需求背景

现场通常不知道 MAC，交换机端已有固定规划，需要把逻辑槽位 `rdma1..rdmaN` 的 IP/网关绑定到真实物理口。名称或 PCI 排序只能形成推荐，不能证明交换机侧接线对应关系。

用户提出用规划 IP 逐口探测网关；若交换机尚未调通，允许逐口人工确认并强制配置，但要明确“人工确认、连通性未验证”。地址冲突、清理失败、无法隔离探测流量不能用该选项绕过。

## 角色与插线的关系

先根据角色、型号、最大支持速率、RDMA 能力和已有绑定确定候选，再考虑链路状态。carrier up 是当前可探测的证据；carrier down 的高速口仍保留为人工配置候选。

例如机器有 16 个 200G 口和 4 个 100G 口，规划只使用 8 个 RDMA 口：

- apply 只配置规划的 8 个槽位，不自动把全部高速口加入规划。
- 已插线的合格空闲 RDMA 口可以参与主动探测，但不能仅凭“刚好有 8 个亮灯”认定槽位映射正确。
- 同型号组数量匹配有助于推荐；最终仍需可靠绑定、唯一探测结果或人工确认。
- 所有高速口都未插线、只有管理口在线时，管理口不能成为 RDMA 兜底候选；高速口保留供确认，连通性标为未验证。

## 主动探测方案与当前实现差异

原方案：临时地址、独立路由表、仅匹配探测流量的规则及专用标记，并持久化清理记录。

工作区实现采用直接构造绑定候选设备的 ARP/ICMP 以太帧，不安装临时 IP、规则或路由。接收路径核对接口、网关地址及请求标识。原本关闭的空闲口会临时拉起，使用恢复记录处理正常清理和异常退出后的恢复。该实现方式的隔离与恢复效果仍需要实机验证。

关键源码：`internal/runner/probe_linux.go`、`probe_recovery_linux.go`、`probe_matching.go`。

探测范围限于物理口 untagged 网络；不创建 VLAN 子接口、不猜 VLAN、不自动修改交换机。网关探测默认开启，可通过 `defaults.rdma_gateway_probe.enabled=false` 关闭；默认尝试 3 次、各项超时 3 秒、链路等待 5 秒。探测无法形成唯一映射时回退到 PCI/硬件顺序并进入 NIC Binding Review，dry-run 不应修改接口状态或发起配置探测。

候选必须能确认空闲：排除业务地址、管理连接、bond/bridge/VRF 等归属以及其他槽位占用。跳过原因应可见。

## 判定与人工处理

收集“规划槽位 × 候选口”结果，再求一对一映射，不能找到第一个可通的口就固定。

| 结果 | 应有处理 |
| --- | --- |
| ARP、ICMP 均成功，完整映射唯一 | 可形成自动绑定 |
| 只有 ARP 成功 | 连通性证据不足，可能网关禁 ping，交给用户判断 |
| 多个口可到同一网关，存在多个映射 | 显示歧义，不任取其一 |
| 全失败或断链 | 可重试或逐口人工确认，标记未验证 |
| 地址冲突、恢复失败、无法保证隔离 | 阻断，要求处理 |

网关可达只证明当时连通性，不证明物理接线符合布线表。

## 保存、复用与已知边界

确认结果保存主机绑定状态，记录 MAC、槽位、来源和配置指纹。重跑需校验设备和规划，失配重新确认。apply 不自动改写原 inventory；discover 可以在用户确认后写回、扩容，并保留原有字段布局。

会话曾指出“部分槽位填 MAC、其余未填”的边界风险：发现结果若重新按物理设备排序，可能破坏已有槽位对应关系。应增加专项验证，确保明确 MAC 绑定先固定、未绑定槽位再匹配。该风险不能仅凭全量 MAC 或全空 MAC 用例通过就关闭；本次未确认已修复。
