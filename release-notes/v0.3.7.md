本版本修复 RDMA 网卡数量被隐式固定为四张的问题，并明确 `discover`、inventory 与 bundle 的职责边界。

## 主要更新

### discover 与 inventory

- `discover` 继续只更新 inventory，不修改 bundle，并在执行结果中明确提示 bundle 保持不变。
- inventory 会根据每台机器实际发现的 RDMA 网卡数量写入 `rdma1..rdmaN`。
- 当重新发现的网卡数量减少时，自动清理该机器多余尾部槽位的 `rdmaN_*` 旧值，避免历史四卡或八卡记录继续参与 apply/check。
- 固定表头中未填写的尾部 RDMA 槽位不再被识别为真实网卡。

### apply 与 check

- 删除 bundle 加载时自动补齐 `ens11np0`、`ens13np0`、`ens15np0`、`ens17np0` 四张网卡的隐藏逻辑。
- inventory 已包含 RDMA 条目时，以该机器的实际条目数量为准；只有 inventory 完全没有 RDMA 条目时，才回退到显式配置的 `defaults.rdma_interfaces`。
- RDMA 带宽分组、RDMA ping 和网卡计数器统一遵循 inventory 数量，不再由 bundle 默认值或旧 `rdma_groups` 生成不存在的测试槽位。
- inventory 只填写 RDMA IP、没有网卡名或 MAC 时，自动生成 `rdma1`、`rdma2` 等逻辑名，继续交给网卡自动发现和 NIC Binding Review 完成绑定。
- 未显式配置路由表时，仍按 RDMA 逻辑顺序使用 `101、102、103...`。

## 兼容性说明

- 现有显式配置 `defaults.rdma_interfaces` 的旧 bundle 仍可使用，但仅在对应机器的 inventory 完全没有 RDMA 条目时作为回退。
- 推荐先执行 `discover` 写回真实 inventory，再执行 `plan`、`apply` 或 `check`。
