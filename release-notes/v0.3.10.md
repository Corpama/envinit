本版本处理 AList 目录缓存中存在零字节悬空对象、但对应 COS 对象下载返回 404 时阻断整个 profile 组装的问题。

## 修复内容

- downloader 识别“目录列表大小为 0、没有 SHA256、实际下载返回 HTTP 404”的悬空条目，输出包含远端路径的明确 WARNING 后继续组装。
- 非零物料或带 SHA256 的物料返回 404 时仍然立即失败，避免静默生成缺少正式包的交付目录。
- HTTP 下载错误改为保留结构化状态码，能够可靠区分 404 与网络错误、鉴权错误及其他服务端异常。
- 增加零字节悬空对象可跳过、非零缺失对象必须失败，以及重复运行仍能复用已完成物料的回归测试。

## 已确认的远端异常

- AList 在 `/data/profiles/ubuntu22.04-x86_64/apt-repo/dists/jammy` 下列出了额外的零字节普通条目 `jammy`。
- 本地正式 Ubuntu profile 中只有 `dists/jammy/main`，不存在 `dists/jammy/jammy` 文件、软链接或零字节对象。
- AList 可以为该残留条目生成 COS 地址，但实际对象返回 404；建议后续从 COS/AList 删除该残留并刷新缓存。

## 升级说明

- v0.3.9 已下载成功的 base、bundle、inventory 和 profile 文件都可以保留。
- 使用 v0.3.10 对应平台 downloader，在原输出目录重新选择相同 profile 即可断点继续。
- 本次仍为轻量发版，不读取、重新打包或上传 profile 大物料。
