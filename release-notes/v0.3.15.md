本版本重点完善多机 XCCL 验收：将单机拓扑选择、跨主机 rail 对齐、逐机环境变量和交付门槛整合为可解释、可覆盖、可回归的完整流程；同时修复重复 Apply 改回网卡名时可能因 Linux `altname` 冲突而留下临时接口名的严重问题。

## XCCL 单机与多机执行模型

- check setup 向导扩展为 `Hosts -> Checks -> Parameters -> Environment -> Review` 五步。
- 只选择一台机器时，Checks 页只保留 XCCL，参数页显示 `execution scope=single_host`，evaluation 固定为 `disabled`；运行使用本地 fork launcher，不创建多机 hostfile 或临时 SSH mesh。
- 选择多台机器时显示 `execution scope=multi_host`，支持 `full_ring` 大环全卡和 `same_index` 多机同号卡布局。
- `ranks=0` 会按各机实际 XPU 数量自动计算 `mpiexec -np`；也可以在参数页或 bundle 中人工覆盖，并校验多机 slot 分配。
- 默认多机参数调整为 `all_reduce / fp16 / 1m -> 2g / 20 iterations`；`same_index` 自动追加 split mode、step 和 operation。
- XCCL Environment 页展示公共变量及需要拓扑发现后逐机解析的变量，Review 显示变量数量，Raw Logs 逐台输出最终 `ENV xccl <host> KEY=value`。
- 同时设置 `XPU_VISIBLE_DEVICES` 和 `CUDA_VISIBLE_DEVICES`，并保持两者顺序一致；昆仑芯运行时优先使用前者。

## XPU/NIC 拓扑与跨主机 rail 对齐

- 本机 XPU/NIC 选择改为全局最优分配，链路优先级为 `PIX -> PXB -> PHB -> NODE -> SYS`；在链路等级相同的前提下平衡 NIC 使用次数，避免逐 XPU 贪心造成后续 XPU 被迫退化。
- 8 张 XPU 配 8 张等价 PIX RoCE 网卡时会形成一对一映射；NIC 少于 XPU 时允许按最优拓扑共享，并明确显示展开后的映射数量。
- topo 解析不再只支持 Mellanox 命名，同时支持 `NIC Legend`、直接 RDMA device 表头，以及 `hns_0`、`bnxt_re1`、`irdma2` 等带数字的通用设备名。
- 每台机器独立解析 Linux 接口、RDMA device、XPU/NIC 拓扑和 socket interface，不要求跨主机使用相同本地网卡名或 `mlx5_N` 编号。
- `xpu_ordering=auto` 在 `full_ring` 中优先保持物理 XPU 顺序，只有跨主机 rail 顺序确实不一致时才解析为 `rail_aligned`；结果详情区分 requested/resolved ordering 及原因，不再把恒等置换误报为重排。
- `BKCL_RDMA_NICS` 和 `BKCL_FORCE_RDMA_NICS_ORDER` 均按每台机器最终 XPU 顺序生成；Raw Logs 同时显示去重后的物理参测网卡数量、按 XPU 展开的变量项数和最终 XPU order。
- inventory 新增可选的 `rdmaN_rail_id`。默认保持为空，程序优先按 RDMA 网段推导 rail；同网段多 HCA 视为共享 fabric，保留 topo/规划顺序。只有自动信息无法表达已知隔离 rail 时才需要跨机器成组填写显式 ID。
- 新增独立算法文档 `docs/xccl-topology-rail-matching.md`，说明本机分配、rail 身份、跨主机置换、共享 fabric 和失败边界。

## XCCL 环境与交付判定

- profile 模板显式提供多机脚本所需的 BKCL/BCCL 默认变量；允许通过 `check.xccl.environment` 覆盖可调项。
- PATH、动态库路径、XPU 可见卡、RDMA NIC 顺序和 socket interface 由 envinit 逐机生成并保持受保护，避免公共环境覆盖本机拓扑结果。
- `machine_class=auto` 复用 Apply/XRE 的 P800 Part Number 识别逻辑，逐台判断 VC/VD；混合机器按木桶原则使用 VC 标准并在日志中说明降级来源。
- `evaluation_mode=auto` 仅应用于已有交付基准的 `all_reduce`。VC 大环、VD 大环和同号卡分别按既定 bus bandwidth 基准与利用率判断；其他 collective 必须选择 manual 或 disabled。
- `validate_topology=false` 可用于已知风险下的强制诊断试跑，但不会跳过本机 topo、物料、动态库和参数等基础校验。
- 多机 runtime 分发继续使用每轮临时 MPICH/XCCL、临时 Ed25519 key 和逐机 rank wrapper；运行前增加一致工作目录和动态依赖检查，结束后只清理本轮拥有的目录、授权行和软链接。

## 网卡重复改名事务修复

- 修复“第一次 Apply 改成统一名称，第二次 Apply 又改回原名称”时，目标名称仍作为 Linux `altname` 存在而触发 `RTNETLINK answers: File exists` 的问题。
- 两阶段改名前先校验目标主名称是否被本轮之外的接口占用。
- 从临时名称切换到目标名称前，删除同一接口上冲突的目标 `altname`。
- 任一步失败时倒序恢复已经移动的接口，并恢复改名前的 administratively UP 状态。
- 错误会明确区分自动回滚完整和回滚不完整，避免接口静默遗留在 `ei-tmpN` 名称下。
- 新增目标名冲突、改回持久化 altname、部分失败回滚等回归测试。

## 兼容性与升级说明

- 现有 inventory 不需要为了升级补填 rail ID；空值是正常默认。
- 旧的显式 CLI bandwidth 调用仍默认只运行 RDMA-CM；交互向导默认同时运行 Verbs 和 RDMA-CM。
- 已有 `check.xccl.environment` 可继续使用，但不能覆盖 envinit 动态生成的 XPU/RDMA 映射和运行路径变量。
- 建议升级后先使用 `check --dry-run` 核对每台机器的 unique RDMA NIC、展开后的 BKCL NIC order、XPU order、resolved ordering 和最终环境，再执行正式多机流量。
