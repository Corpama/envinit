本版本精简 downloader 的最终交付目录，避免同一份交付中同时出现 `examples/`、`planning/templates/`、两份 inventory 和两套系统 bundle，降低现场选择错误文件的风险。

## 调整内容

- 轻量 base 包不再携带 `examples/`、`planning/templates/`、默认 Ubuntu bundle 和重复 inventory。
- downloader 根据用户选择的系统 profile，只下载对应的 bundle，并统一保存为 `planning/bundle.json`。
- 公共 inventory 只下载一份，并统一保存为 `planning/inventory.csv`。
- 最终 `planning/` 目录只包含 `bundle.json` 和 `inventory.csv`，现场命令参数保持不变。
- 仓库中的 Ubuntu/Kylin bundle 样例仍作为发版源文件保留，但不再进入最终交付目录。

## 验证内容

- 增加 downloader 资产命名回归测试，确保 bundle 和 inventory 只写入单一 `planning/` 目录。
- 增加组装结果测试，确认不再生成 `examples/`、`planning/templates/` 和 `inventory.sample.csv`。
- 通过 downloader 单元测试、全量 Go 测试、发布脚本语法检查和补丁格式检查。

## 升级说明

- 新版 downloader 在新的空输出目录中运行时，会生成精简后的目录结构。
- downloader 不会主动删除已有目录中的文件，以免误删现场修改过的规划表或模板；如果复用 v0.3.12 的输出目录，旧的 `examples/`、`planning/templates/` 和 `inventory.sample.csv` 仍会保留。
- 本次只调整轻量 base、manifest 资产名称和 downloader 组装结果，不重新读取、打包或上传 profile 大物料。
