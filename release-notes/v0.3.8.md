本版本完善离线交付物料的按需组装流程，统一 apply/discover 网卡识别逻辑，并修复 discover 远程目标绑定和 XCCL 实机验收中的关键问题。

## 主要更新

### 轻量发版与 downloader 物料组装

- GitHub Release 不再从 COS 下载并重新打包数 GB 的 `data` 物料，只发布 manifest、bundle、inventory 样例和跨平台 downloader，显著缩短发版时间并减少 COS 流量。
- downloader 根据所选 Ubuntu 22.04 或 Kylin V10 SP3 profile，递归拉取 AList 中对应的物料目录，并直接组装为可交付的 `env_tool/data`。
- 物料下载支持并发、单文件大小与 SHA256 校验、`.part` 临时文件和完成标记；中断后再次执行会跳过已验证文件并继续下载。
- Linux、macOS 和 Windows 分别处理可执行权限与文件落盘差异，并过滤 `.DS_Store`、AppleDouble 和 `Thumbs.db` 等平台杂项文件。

### 统一网卡自动发现与绑定

- 新增公共网卡判断模块，apply 和 discover 共用“硬绑定、硬件分组、规划数量匹配、分层评分”逻辑，避免两个入口对同一机器给出不同结论。
- 综合使用 inventory 中的 MAC、接口名、IP，以及网卡型号、最大/当前速率、RDMA 能力、MTU、链路、PCI 和地址分布进行判断；当前未配置 IP 或链路未接通不会被直接排除。
- TUI 增加简短的 `Why` 和置信度提示，人工选择始终覆盖自动推荐；同一物理网卡不能重复绑定或同时承担管理网与 RDMA 角色。
- `--yes` 只自动接受 exact/strong 结果，weak、ambiguous 和 conflict 必须进入交互确认，防止无人值守模式静默采用不确定映射。
- 从管理网和 RDMA 候选中按地址语义过滤 `169.254.0.0/16`、loopback、unspecified、multicast 和广播地址，不依赖特定接口名黑名单。

### discover、inventory 与远程目标

- `--hosts` 支持 `inventory-id=SSH地址` 显式映射；也可以直接输入临时 IP，连接后读取远端 hostname，再匹配已有行或自动追加新的 inventory 行。
- inventory hostname 出现多行歧义时停止写回并要求显式映射；显式身份与远端 hostname 不一致时提示警告，但仍只更新指定行。
- discover 根据最终确认的 RDMA 数量自动扩展 CSV/TSV 的 `rdmaN_*` 表头，复用模板字段布局；写回采用临时文件和原子替换。
- TUI 和日志展示管理网/RDMA 判断依据、inventory RDMA 槽位变化以及每个逻辑槽位的最终绑定，便于现场复核。
- check 同样支持 `inventory-id=SSH地址`，将 inventory 身份与实际控制地址分离；不会像 discover 一样自动新增 inventory 行。

### XDR/XCCL 实机检查

- `xpu-smi topo -m` 同时兼容 `NIC0 + NIC Legend` 和直接以 `mlx5_N` 为列名的输出，并能清理终端 ANSI 控制字符，修复找不到 NIC 列或 NIC legend 的问题。
- XCCL perf 命令与现场 SOP 对齐，使用 `-O <collective> -x 1 -c 0`；`-c 0` 关闭正确性校验开销，结果明确标记为性能模式。
- 默认测试范围调整为 `1 KiB` 到 `256 MiB`、步进倍数 2，并输出每个 size 的 out-of-place 和 in-place 完整性能曲线，而不再只显示单个汇总点。
- 多机 Hydra 启动会在所有目标上预创建相同工作目录，并显式传入 `-wdir`，修复远端工作目录不存在导致的启动失败。
- 拓扑映射缺失、IB device 不在 topo 中或性能输出不完整时给出更明确的错误信息，方便定位 inventory、sysfs、XPU/NIC 拓扑和运行时问题。

### 文档与样例

- README 按外层功能、命令参数、内部逻辑、结果和故障处理的顺序补全 downloader、plan、apply、discover、check 说明。

## 使用注意事项

- downloader 会递归下载所选 AList profile 根目录中的全部文件，交付前应确保 `/data/profiles/<profile>` 只包含需要下发的正式物料。
- `data/...` 路径仍相对执行 `env_init` 时的当前目录，现场应先进入组装完成的 `env_tool/` 再执行命令。
- 首次在新机器上执行 apply 时，建议先运行 `plan`；网卡自动判断出现 weak、ambiguous 或 conflict 时，应在 TUI 中人工确认。
- XCCL 单机检查只验证机内 XPU 集合通信，不能代替跨机 RoCE、交换网络和实际 PD 分离链路验收。
