本版本修复 downloader 将正常的 `planning/bundle.json` 误判为 AList 下载错误、导致尚未进入 profile 物料下载就退出的问题。

## 问题原因

- COS 为 bundle JSON 正常返回 `Content-Type: application/json`。
- 旧 downloader 只根据 Content-Type 判断错误，把所有 JSON 响应都当作 AList 接口错误，因此直接打印完整 bundle 内容并退出。

## 修复内容

- JSON 响应只有同时包含 AList `code`、`message`、`data` 错误信封且 `code != 200` 时才作为下载错误。
- 普通 bundle、manifest 衍生资产和 profile 中的合法 JSON 文件按正常文件写入，并继续执行 SHA256 或大小校验。
- AList 错误信封仍在创建 `.part` 文件前失败，不会把错误正文写入交付目录。
- 合法 JSON 的网络字节正常计入聚合进度和下载速度；AList 错误正文不计入物料完成进度。
- 增加合法 bundle JSON、AList JSON 错误、文件内容和进度字节数回归测试。

## 升级说明

- 日志显示 `Downloading env_tool v0.3.9` 或更早版本时，必须先替换 downloader；仅重跑旧文件不会获得修复。
- v0.3.12 可以直接使用原输出目录，已经组装的 base 和校验成功的文件会继续复用。
- 本次只更新 downloader，不重新读取、打包或上传 profile 大物料。
