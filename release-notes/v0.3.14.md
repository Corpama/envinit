本版本重点升级 `envinit check`：新增完整的交互式配置与实时结果 TUI，将 Ping、Bandwidth 和 XCCL 的长时间测试从“等待最终输出”改为可选择、可观察、可中止、可复测的诊断流程；同时补充 Bandwidth Verbs/RDMA-CM 双路径验证、自动带宽门槛和可视化能力。

## 交互式 check 配置

- 交互终端中省略 `--hosts` 会进入 `Hosts -> Checks -> Parameters -> Review` 四步向导，不再要求先在命令行拼接主机列表。
- 支持在向导中选择参测主机及 Ping、Bandwidth、XCCL stage，并临时覆盖本轮测试参数；不会改写 `bundle.json`。
- Ping 可配置包数、payload 和超时。
- Bandwidth 可配置 Verbs/RDMA-CM 模式、时长/迭代次数、消息大小、QP 数、GID index、并发批次、端口、host/XDR 内存后端和吞吐门槛。
- XCCL 可配置 collective、消息范围与步进、warmup、迭代次数、数据类型、超时、XDR/supernode、socket interface 和最低 bus bandwidth。
- 自动化与非交互环境保持兼容：继续显式传入 `--hosts`；新增 `--no-tui` 强制使用普通文本输出。

## 实时结果 TUI

- Ping、Bandwidth Verbs、Bandwidth RDMA-CM、XCCL 在测试开始前显示完整待测矩阵，并将结果原位更新为 `WAIT/RUNNING/PASS/FAIL/ABORT`。
- 每个 stage 提供 `Results / Counter Delta / Raw Logs` 三个页面；原有 NIC/RDMA counter 统计与失败规则保持不变。
- `Space` 打开完整详情，Ping 保留完整丢包信息，Bandwidth 分别展示 client/server 命令输出和错误。
- `PgUp/PgDown` 翻阅主列表、Counter Delta 或 Raw Logs；`Ctrl+U/Ctrl+D` 独立翻阅详情，避免详情面板抢占主内容翻页。
- 支持终端尺寸变化和宽/窄屏布局，按键提示固定在屏幕底部；超宽表可横向移动。
- `[`/`]` 切换 stage，`Tab/Shift+Tab` 切换页面。测试运行时按 `q` 中止光标所指的 Ping/Bandwidth 项；按一次 `Esc` 中止当前 stage，短时间内连续两次 `Esc` 中止整轮 check。
- 完成后可选中一条 Ping 或 Bandwidth 链路按 `Enter` 原位重测；重测日志会追加到 Raw Logs，且不会覆盖首次检查的总体结论和 counter 快照。

## Bandwidth 双模式与智能判定

- Bandwidth 拆分为独立的 `BW Verbs` 和 `BW RDMA-CM` stage：
  - Verbs 使用管理网络交换控制信息，显式选择两端 IB device 与 GID index，不启用 `-R`。
  - RDMA-CM 使用规划的 RDMA IP 建立连接并启用 `-R`，用于验证 CM/路由路径。
- 交互向导默认使用更适合持续压测的 duration 模式，并支持配置多个 QP；旧 CLI 调用默认仍保持原有 RDMA-CM 行为。
- `check.bandwidth.min_gbits` 默认改为 `"auto"`：探测两端网卡最大支持速率，按木桶效应取较小值，并以其 70% 作为逐链路通过门槛。
- `min_gbits=0` 表示只记录、不限制；正数继续表示固定 Gbps 门槛，兼容已有人工基准。
- Results 页按 `p` 切换列表与双向热力图；两个 client/server 方向同时展示并明确标注，方向键选择链路，详情显示实测值、baseline、门槛和利用率。

## XCCL 展示增强

- Results 按 out-of-place 和 in-place 分组，不再将同一消息大小的两种模式交错展示，也不再插入重复的 SUMMARY 行。
- 性能行实时填入 size、time、AlgBW 和 BusBW，最终判定档位使用 `EVAL=*` 标记。
- 按 `p` 切换表格与折线图；折线图分别展示 AlgBW 和 BusBW，按 `m` 切换 out-of-place/in-place，按左右键查看具体消息大小和数值。
- 启动、分发或 mpirun 失败时增加独立错误行，完整诊断信息保留在详情和 Raw Logs。

## 网络发现与兼容性修复

- discover 候选接口过滤补充 OVN/OVS 等虚拟网络接口，避免将 `ovn0` 错选为管理或 RDMA 网卡。
- Bandwidth Verbs 参数页明确提供 GID index 配置，RDMA-CM 模式则继续由规划的 RDMA IP 完成路径选择。
- check 启动的本地与 SSH 子进程支持取消和清理，Bandwidth client/server 与 XCCL 共享进程均纳入中止流程。
- 保持 `go build -o env_init cmd/envinit/main.go` 的单文件入口构建方式兼容。

## 升级说明

- 推荐现场直接运行 `sudo ./env_init check --inventory planning/inventory.csv --bundle planning/bundle.json` 进入向导。
- 如果现场自动化依赖旧行为，请继续显式传入 `--hosts`；需要纯文本输出时增加 `--no-tui`。
- 默认 bundle 的 Bandwidth 门槛从“不限制”调整为 `"auto"`。如果只希望采集数据而不按吞吐判失败，请显式设置 `"min_gbits": 0`。
