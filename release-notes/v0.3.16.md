本版本统一重构 envinit 的自动备份位置，修复 Kylin legacy `network` 在重复 Apply 后把同目录 `ifcfg-*.bak.*` 误识别为真实网卡配置、重复拉起旧 IP 的问题；Ubuntu netplan、APT/YUM 源及其他托管文件也统一使用同一套可追溯备份目录。

## Kylin 重复 Apply 修复

- 旧实现会把 `/etc/sysconfig/network-scripts/ifcfg-xgbe8` 原地改名为 `ifcfg-xgbe8.bak.YYYYMMDD_HHMMSS`。
- legacy `network` 仍可能把该文件作为接口配置扫描并执行，导致新旧配置同时占用同一 MAC/IP，出现 `some other host already uses address` 或 `RTNETLINK answers: File exists`。
- 新版本不再在 `network-scripts` 中创建同目录备份；ifcfg、route 和 rule 会移至统一备份根目录。
- 执行 `network` stage 时，会自动迁移旧版本严格匹配 `.bak.YYYYMMDD_HHMMSS` 格式的 ifcfg、route、rule 和 netplan 备份。人工命名或不符合 envinit 旧格式的文件不会移动。

## Ubuntu、Kylin 与其他备份统一

- 新增 `defaults.backup_root`，默认值为 `/var/lib/envinit/backups`。
- Ubuntu netplan、Kylin ifcfg/route/rule、APT/YUM 源、udev/systemd/sysctl 等托管文件、离线物料覆盖目标、`post_tasks` 覆盖目标和 RDMA 兼容文件都使用统一备份逻辑。
- 备份目录按“时间批次 + 原绝对路径”组织，例如：

```text
/var/lib/envinit/backups/20260903_164904/etc/netplan/00-kunlun-bond.yaml
/var/lib/envinit/backups/20260903_164904/etc/sysconfig/network-scripts/ifcfg-xgbe8
```

- 同一秒内同一路径重复备份时追加 `.1`、`.2`，避免覆盖已有备份。
- 备份使用原子移动。自定义 `backup_root` 必须使用绝对路径、与被备份内容位于同一文件系统，并且不能放在 netplan、network-scripts、APT 或 YUM 的活动配置目录中。
- 如果备份目录创建或移动失败，envinit 会保留原文件并停止，不会继续覆盖目标配置。

## 配置与兼容性

- 旧 bundle 无需修改；省略 `backup_root` 时自动使用 `/var/lib/envinit/backups`。
- Ubuntu 和 Kylin 示例 bundle 已显式加入默认备份根目录，便于交付时检查或按现场路径调整。
- `backup_existing_netplan`、`backup_existing_network`、`disable_existing_apt_sources` 和 `disable_existing_repos` 的启用语义保持不变，仅改变备份文件的保存位置。
- 旧版遗留的网络同目录备份只会在执行 `network` stage 时迁移；已有机器升级后应先查看 plan，再运行 network stage 完成迁移和配置重放。
